## [Unreleased]

### Added
- Data phase database schema: 18 migrations defining tables for cards, card types, classes, talents, keywords, heroes, hero profiles, card printings, card legality, precons, rules text versions, errata bulletins, meta snapshots, and staple stats, with foreign keys, indexes, and constraints. Includes a feature test validating the full schema (#10).
- `php artisan data:ingest-cards` command to ingest Flesh and Blood card data from the-fab-cube/flesh-and-blood-cards, populating cards, card types, classes, talents, keywords, legality, and hero/hero profile seed rows via idempotent upserts keyed on a new `cards.source_id` column (#11).
- `php artisan data:ingest-pricing` command to refresh market pricing from tcgcsv.com per-set CSV data, updating `card_printings.price_cache` and `price_updated_at` by matching the printed card number against `cardvault_print_id`, with a `--category` option for per-category ingestion. Adds the supporting `CardPrinting` model and `CardFactory`/`CardPrintingFactory` factories (#12).
- `php artisan data:ingest-printings` command to ingest card print variations (set code, rarity, finish, art variant, cardvault print ID) from the unofficial cardvault API by matching existing cards by exact name, automatically mirroring art to DigitalOcean Spaces as optimized WebP, with a new `card_printings.image_source_hash` column enabling idempotent re-runs (#13).
- `php artisan data:ingest-rules-text` command to fetch the Comprehensive Rules plain-text file from rules.fabtcg.com and insert a versioned snapshot into `rules_text_versions`, computing `diff_from_previous` (added/removed/changed rule-section keys) on every run without overwriting prior versions. Adds the `RulesTextVersion` model and factory (#14).
- `php artisan data:ingest-errata` command to scrape the fabtcg.com errata bulletins index and populate `errata_bulletins` with each bulletin's number, URL, published date, and article content, resolving `affected_card_ids` by matching article headings against card names case-insensitively. Bulletins are cached once and never re-scraped — only the index is re-checked for new entries — and articles that don't match the expected page structure are flagged and skipped rather than persisted partially. Adds the `ErrataBulletin` model and factory (#15).
- `php artisan data:ingest-meta` command to ingest hero win-rate and sample-size data from fabtcgmeta.com (JSON API) and fablazing.com (React Router SSR payload) into meta_snapshots, resolving each observation against existing hero-type cards and canonicalizing formats (CC, LL, SAGE, GAGE) from the formats table at runtime. Adds the MetaSnapshot model, MetaSnapshotFactory, and hero() state on CardFactory (#16).
- `php artisan data:ingest-staples` command to scrape per-hero card inclusion-rate stats from fabrec.gg (`/hero/{slug}` pages) into staple_stats, resolving hero cards by card_type_id and other cards by case-insensitive name match, with updateOrCreate keyed on hero_id/card_id/source and flag-and-skip handling for fetch failures, malformed rows, and unmatched card names. Adds the StapleStat model and StapleStatFactory; uses native PHP 8.4 Dom\HTMLDocument/Dom\XPath without adding new Composer dependencies (#17).
- `php artisan data:ingest-hero-selection` command to ingest official hero playstyle tags, lore, and format legality from fabtcg.com/hero-selection JSON API into hero_profiles, heroes, and card_legality, resolving each fabtcg hero against hero-type cards by case-insensitive name match, with HTML entity decoding/whitespace normalization of bio text and mapping of fabtcg format keys (cc, living-legend, project-blue) to canonical abbreviations (CC, LL, SAGE) — unmapped keys (blitz, commoner, ultimate-pit-fight) are flagged once per run but not written. As an official-source overlay, it overwrites IngestFabCubeCards legality entries for the three mapped formats without deleting rows, with flag-and-skip handling for unmatched heroes, missing profiles, empty tags/bios, unseeded formats, and unrecognized statuses. Adds the IngestHeroSelectionMetadataCommandTest feature test and fabtcg-hero-selection.json fixture (#18).
- `php artisan data:check-sources` command and supporting `pipeline_runs`/`source_sync_state` tables to run Data ingestion and (future) Enrichment AI on a schedule without wasting cost on unchanged sources: a `SourceFreshnessChecker` service probes each of 8 external sources for a cheap freshness fingerprint (GitHub commit SHA for fab-cube, HTTP ETag/Last-Modified/content-hash elsewhere) and only re-ingests a source whose fingerprint changed since its last successful pull; a `PipelineRunRecorder` logs every Data/Enrichment invocation and enforces a per-phase concurrency lock with stale-run reconciliation; and a `PipelineRunGate::enrichmentShouldRun()` service exposes a reusable cooldown + AI-relevant-source-change gate for a future Enrichment orchestration command to call. Scheduled daily at 09:00 with `--source`, `--check-only`, `--force`, and `--triggered-by` options for manual/local testing (#38).
- `php artisan enrich:run` command wiring the Enrichment pipeline's orchestration skeleton: a chained sequence of queued jobs (build knowledge base → per-card explainer/combo/synergy fan-out via `Bus::batch` → validate → publish) with per-job retry/backoff, rate-limited LLM/embedding job stubs, and idempotency guard clauses that skip cards already up to date unless `--fresh` is passed. Supports `--only` to run a subset of steps, `--card` to enrich a single card inline, and a local-only `--via=cli` transport that shells out to the `claude` CLI with JSON-schema response validation and retry (refused in production). Scheduled weekly on Mondays at 10:00. All job bodies are stubs — this issue wires the dispatch/retry/idempotency scaffolding only, with no real AI/embedding logic yet (#31).
- Implements the `enrich:run` knowledge-base step: `KbChunker` splits Comprehensive Rules text and errata bulletins into section-sized chunks (merging trivial sections, splitting oversized ones) and gathers validated explainer/combo/synergy notes as "enrichment-side memory," excluding draft content. `VoyageEmbeddingClient` embeds chunks through the Voyage AI REST API (`VOYAGE_API_KEY`, `voyage-3.5` by default), and `BuildKnowledgeBase` fans embedding work out into rate-limited `EmbedKbChunks` jobs, writing `kb_documents.content`/`embedding`/`embedding_model`/`trust_status`/`source_type`/`source_ref`/`effective_date`. Rebuilding a source deletes and reinserts its rows at `version=1`; a separate sweep re-embeds any `kb_documents` row whose `embedding_model` has fallen behind the configured model or whose embedding is missing, even outside the current run's fresh content (#32).
- Implements the `enrich:run` card explainer step: `GenerateCardExplainer` grounds each card on its `functional_text`, its keywords' glossary text, top-k `ground_truth`-trust KB chunks (retrieved by `KbRetriever` via Voyage query embeddings, ranked natively with pgvector `<=>` on Postgres or in-PHP cosine similarity elsewhere), and any errata bulletin listing the card, renders the versioned prompt package at `skills/enrichment/card-explainer/`, and writes the structured result (`explainer_text`, `cited_rules[]`) to `card_explainers` as `status=draft`. Adds `source_hash`/`prompt_version` columns to `card_explainers` so a card is only regenerated when its upstream data or the prompt package actually changed. As the first AI task to run for real, this also implements `ApiLlmTransport` (previously a stub) on the new `anthropic-ai/sdk` dependency, using a forced tool call to get schema-constrained structured output with re-prompt-on-mismatch, and adds a configurable per-task model tier (`config('enrichment.models.card_explainer')` / `ENRICHMENT_MODEL_CARD_EXPLAINER`, defaulting to a Sonnet-tier model) (#33).
- Implements the `enrich:run` combo-tagging step: `TagCardCombos` replaces the stub with a real structured-output Claude call, pooling cards sharing a class or talent with the target card as candidates, ranking them by on-the-fly embedding similarity, grounding on prior validated combo examples from `kb_documents` (retrieved via generalized `KbRetriever` with trust_status/source_type filtering), proposing combos with a Haiku-tier model, and writing accepted proposals as draft `combo_pairs` rows with `source_hash`/`prompt_version`/`generated_at` columns enabling hash-based idempotency (mirroring card-explainer). Filters proposals for unknown cards, self-pairs, blank descriptions, and duplicates; preserves existing validated rows and never re-proposes them as drafts; skips entirely when the candidate pool is empty or when an up-to-date combo row already exists. Adds `ComboCandidateRetriever` (retrieves and ranks candidates), `ComboTaggingPromptBuilder` (renders versioned prompt package), `VectorSimilarity` (extracted stateless vector math for reuse), and new config keys `ENRICHMENT_MODEL_COMBO_TAGGING`/`ENRICHMENT_RETRIEVAL_COMBO_CANDIDATE_TOP_K`/`ENRICHMENT_RETRIEVAL_COMBO_POOL_LIMIT`/`ENRICHMENT_RETRIEVAL_COMBO_EXAMPLES_TOP_K` (#34).
- Implements the `enrich:run` synergy-tagging step: `TagCardSynergies` replaces the stub with a real structured-output Claude call, grounding on the established `synergy_tags` vocabulary and validated synergy KB chunks (retrieved via `KbRetriever` with `TRUST_VALIDATED` + `SOURCE_SYNERGY` filtering), proposing tag assignments and new-tag candidates with a Haiku-tier model, and writing accepted assignments as draft `card_synergy_tags` rows with `source_hash`/`prompt_version`/`generated_at` columns enabling hash-based idempotency (mirroring card-explainer and combo-tagging). Assignments are discarded unless they reference a tag in the supplied vocabulary; new-tag proposals land as unvalidated `status = 'proposed'` `synergy_tags` rows (separate from the `status = 'approved'` vocabulary used by later cards) and are discarded unless their name is non-blank, non-duplicate, and does not collide with existing tag names. Existing validated rows are preserved and never re-proposed as drafts; skips entirely (no KB retrieval, no LLM call) when the card has no functional text or when an up-to-date synergy row already exists. Adds `SynergyTaggingPromptBuilder` (renders versioned prompt package), a new `synergy-tagging` skill package with versioned `prompt.md`/`schema.json`, two migrations (`add_status_to_synergy_tags`, `add_idempotency_columns_to_card_synergy_tags`), updated `EnrichmentPlanner` scoping to detect stale draft rows, a `proposed()` state on `SynergyTagFactory`, and new config keys `ENRICHMENT_MODEL_SYNERGY_TAGGING`/`ENRICHMENT_RETRIEVAL_SYNERGY_EXAMPLES_TOP_K` (#35, #45).
- Implements the `enrich:run` self-validation step: `ValidateEnrichment` replaces the stub with the gate between `draft` and `validated`. For `card_explainers`, a new `ExplainerGroundingChecker` deterministically verifies every `cited_rules` entry exists in the latest `rules_text_versions` snapshot (independent of KB embedding freshness), short-circuiting to a flagged/draft row with no LLM call on a bad citation; explainers that ground cleanly get an LLM topical-consistency judgment via `ExplainerValidationPromptBuilder` (new `explainer-validation` skill package) and promote to `validated` only on a consistent verdict, recording a confidence (clamped to `[0, 1]`) and flag reason either way. For `combo_pairs`/`card_synergy_tags`, a new `ComboSynergyPlausibilityAuditor` scores every draft row by embedding cosine similarity — an interim substitute for self-play validation, which is deferred until the Play phase's game engine exists — but never itself promotes a row; promotion requires a pre-existing `human_signoff_at` timestamp from human review. Adds `grounding_confidence`/`grounding_flag_reason` to `card_explainers` and `plausibility_score`/`human_signoff_at` to `combo_pairs`/`card_synergy_tags` via three additive migrations, and a new config key `ENRICHMENT_MODEL_EXPLAINER_VALIDATION` (#36).
